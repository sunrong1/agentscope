### Q1（ToolCallState 状态机）✅✅ 强

**你答**："local 同步 / external 异步 / 同一结果 / 面向接口"

**技术名**：**"Strategy Pattern"**（可替换算法）

| 维度 | Local tool | External tool |
|---|---|---|
| **执行位置** | Agent 进程内 | 外部进程 |
| **同步性** | 同步 | 异步 |
| **失败处理** | raise | 走 Event 通道 |
| **HITL** | 直接暂停 | 标记 SUBMITTED |

**架构师视角**：
> **"Same state machine, different execution path"**
> - ToolCallState 是抽象协议
> - 两条路径是具体实现——**可替换**
> - **判断标准**：实现有 N 种且可相互替换 = Strategy Pattern

---

### Q2（Discriminated Union）✅✅ 强

**你答**："case 判断 / 标签联合 / 扩展方便 / 比继承简单"

**技术名**：**"Discriminated Union"**（也称 Tagged Union / Sum Type）

**Pydantic 怎么用**：
```python
class MyUnion(BaseModel):
    block: TextBlock | ThinkingBlock | ToolCallBlock = Field(
        discriminator="type"  # ← Pydantic 自动 dispatch
    )
```

| 维度 | 继承 | Discriminated Union |
|---|---|---|
| **耦合度** | 子类必须继承父类 | 完全独立 |
| **多继承** | 复杂 | 可以同时是多个 union 的成员 |
| **新增类型** | 改父类影响所有 | 新建 class + 加进 union |
| **JSON 序列化** | 父子字段混淆 | 单一 type discriminator |

**架构师视角**：
> **"Discriminated Union > Inheritance for closed sets"**
> - **"is-a"**（Dog is Animal）→ 继承
> - **"either-or"**（Text or ToolCall）→ Union
> - **Block 是平级内容**——**用 Union 对**

---

### Q3（两个 State Machine）✅✅ 强

**你答**："call/result 不同概念 / 不同阶段 / 关注点分离"

**关键洞察**——**两个 state machine 跟踪"不同时间窗"**：

| 时间 | 跟踪谁 | 状态机 |
|---|---|---|
| **执行前** | call 生命周期 | `ToolCallState`（PENDING → ASKING → ALLOWED → SUBMITTED）|
| **执行后** | result 状态 | `ToolResultState`（RUNNING → SUCCESS/ERROR/INTERRUPTED/DENIED）|

**转换点**：execution 开始时 = `allowed → submitted`（external）

**vs "Unified state"**：
- 合并 = 5 × 5 = 25 个状态——**状态爆炸**
- 合并 = 125 个转换——**不可维护**

**为什么不能合并 DENY/DENIED**：
- `ToolCallState.DENY`（asking 阶段，permission 决定）
- `ToolResultState.DENIED`（result 阶段，执行被拒）
- **时机不同**——**不能合一**

**架构师视角**：
> **"Two state machines for one lifecycle"** = **Phase-based state tracking**
> - Pre-execution：业务逻辑（permission / HITL）
> - Post-execution：技术逻辑（结果状态）
> - **判断标准**：状态属于哪个阶段？用对应 state machine
