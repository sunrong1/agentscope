### 今日最大收获（5 个）

#### 1. **`_clear_unreserved_read_cache` 是 W3 收官的最完美一笔** ⭐

**5 句话教我**：**"资源跟着 context 走"**——**context 是 cache 命运**——**不是工具**。

- Read 工具 → 产生 cache
- Context 压缩 → 决定 cache 生死
- **AgentScope 选"context 是 cache 命运"**——**而不是"工具是 cache 主人"**

**纠正我的小错**："Write 没意义"——**错**——**Write 完全有意义**——**只是不产生 cache**。

#### 2. **3 个资源管理策略** ⭐

| 策略 | 体现 |
|---|---|
| **Lazy Cleanup** | 不主动清理，只在 compression 时清理 |
| **Reference Counting** | 压缩 = 减少引用 → 没引用必须清 |
| **LRU** | 压缩 = "最近用"边界 → boundary 前清 |

**这 3 个不是"资源管理 3 种选择"**——**是 3 个"层"**——**Lazy 是触发器，RC 是数据结构，LRU 是策略**。

#### 3. **model 适配三件套**——**框架边界用 dict**

| 函数 | 关键 |
|---|---|
| `_get_system_prompt` | transformer pattern（所有 middleware 必须应用）|
| `_prepare_model_input` | dict 输出（cross-provider boundary）|
| `_call_model` | layered resilience（retry + fallback）|

**W3-D5 段 2 学到的"transformer vs chain"和"dict vs typed"**——**是 framework 设计的 2 个判断标准**。

#### 4. **Q2 答错**——**"写文件操作无意义"**——**纠正

**错的原因**：
- 我读时把 "Write 不产生 cache" 简化成 "Write 没意义"
- **逻辑跳跃**——**"不产生 cache" ≠ "没意义"**

**教训**：
- **简化要保真**——**跳过中间环节会错**
- **每一步都要经得起挑战**
